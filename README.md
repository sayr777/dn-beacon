# DN·Beacon — Портфолио решений на базе динамической BLE-метки

Коммерческие решения на базе промышленного образца [dynamic-iBeacon](https://github.com/sayr777/dynamic-iBeacon) — промышленного BLE-маяка с AES-128 anti-fraud механизмом динамических идентификаторов. ML-предиктивная аналитика и Edge-ML — проектируемые модули платформы; их готовность и эффект требуют подтверждения на данных пилота. Заявленный ресурс базовой метки — до 10 лет, не гарантия для конфигураций с датчиками и ML.

## Аппаратная платформа

| Параметр | Значение |
|---|---|
| Чипсет | nRF52832 (модуль YJ-16013) |
| Формат сигнала | iBeacon (Apple) · Eddystone-UID/URL (Google) · AltBeacon |
| Корпус | AK-W-70-4, IP67, 70 × 40 × 20 мм |
| Батарея | ER14505H-LD (Li-SOCl₂, 2700 мАч) |
| Срок службы батареи | **до 10 лет** |
| Ток (день / ночь) | 5.2 µА / 1.1 µА |
| Интервал передачи | настраиваемый |
| Anti-fraud | AES-128 ECB, динамический ID каждые 5 мин (настраивается); ограничивает копирование статического ID, но не исключает replay/relay и не заменяет аутентификацию доступа |
| ML-предиктивная аналитика | Проектируемый серверный модуль: оценка рисковых зон и повторяемости инцидентов после сбора размеченных данных |
| Edge-ML | Проектируемый локальный инференс на бортовом контроллере/шлюзе: классификация удара, вибрации и штатной работы; обучение вне устройства |
| TinyML | Опциональное направление на метке с датчиками; требует проверки памяти, BLE-прошивки, задержки и энергобюджета nRF52832 |
| Дальность | до 70 м (регулируется) |
| Рабочая температура | −40°C … +85°C |

## Архитектура аналитики и ограничения

- **Плюсы BLE-платформы:** стандартный формат и широкая совместимость, низкое энергопотребление, работа без GPS/SIM и внутри помещений, регулируемые дальность и частота. Сменный AES-идентификатор сокращает окно полезности перехвата и затрудняет долговременное связывание метки.
- **Открытый радиоэфир:** advertising-пакет доступен любому приёмнику в радиусе. Шифрование полей не делает канал конфиденциальным и не защищает от глушения.
- **Replay/relay:** свежий пакет можно повторить в пределах окна или ретранслировать из другой точки. Нужны дедупликация, временная проверка, контекст нескольких датчиков, а для критичных действий — challenge-response/второй фактор.
- **GATT/OTA и ключи:** канал настройки защищается отдельно: аутентификация, закрытые характеристики, подписанная прошивка, уникальные ключи, отзыв и аудит. Дефолтные ключи недопустимы.
- **Приватность:** журналы присутствия и перемещений минимизируются, разграничиваются по ролям и удаляются по установленному сроку. Сам маяк обычно сообщает собственный ID и не «считывает телефон» прохожего.
- **BLE-платежи ≠ iBeacon-оплата:** кейсы «ВЖУХ»/«Волна» подтверждают BLE как канал iPhone ↔ терминал, но требуют активного приложения, двусторонней сессии, одноразовых платёжных данных, привязки суммы/терминала и подтверждения пользователем. RSSI не является фактором авторизации.
- **BLE mesh ≠ гарантированная связь:** bitchat подтверждает multi-hop/store-and-forward без Internet, но доставка зависит от плотности, TTL, дублей, фоновых ограничений ОС и батареи. Стандартный Mesh relay со сканированием имеет иной энергопрофиль, чем advertising-маяк; питаемые relay и резервные шлюзы — базовый вариант для промышленного SLA.
- **Anti-fraud ≠ контроль доступа:** ротация ID не доказывает личность оператора и физическую близость; для разрешения запуска нужна отдельная проверка полномочий и защищённая аутентификация.
- **Edge-ML:** обработка на питаемом бортовом контроллере позволяет работать без облака. Предлагаемые классы: удар, поворот на месте, верхнее положение вил, неровность пола, неизвестное событие. Неизвестные события не следует молча отбрасывать.
- **ML-предиктивная аналитика:** серверный анализ накопленной истории; это не подтверждённое предсказание столкновения в реальном времени. Пороговые правила сравниваются с моделью на отдельных сменах и машинах; метрики — пропуски и ложные тревоги на машино-час.
- **TinyML:** перенос компактной модели на датчик — отдельный этап после измерений. Заявленные микроамперы и ресурс базового маяка нельзя переносить на IMU, постоянное сканирование или инференс.
- **Радиопозиционирование:** BLE RSSI пригоден для обследуемого зонального мониторинга, но не гарантирует безопасную дистанцию в металлическом складе. nRF52832 не поддерживает CTE для стандартного BLE AoA; AoA требует другой совместимой аппаратуры. Точная локализация и безопасность нуждаются в отдельной валидации.
- **Безопасность:** детекция удара фиксирует уже случившееся событие, а не предотвращает наезд. Мониторинг и предупреждения не заменяют ограждения, регламенты и сертифицированные защитные системы. Любое управление техникой — только через согласованный с изготовителем интерфейс после оценки риска.
