Статья 02 · TinyML для реального устройства

Не «нейросеть в маяке», а измеримый сенсорный конвейер

TinyML полезен, когда локальная модель сокращает трафик, задержку или энергозатраты относительно прозрачного алгоритма. Для DN·Flow AI первая задача — классификация состояния движения и механического события по IMU, а не вычисление координаты по BLE.

Короткий вывод: готовый образец на nRF52832 не ограничивает продукт. Простые модели можно проверить на нём, а сенсорную TinyML-метку целесообразно сразу проектировать на nRF52840 или nRF5340 с большим запасом RAM/Flash. Все варианты используют общий формат событий и один Edge-контур; ресурсы и автономность подтверждаются на выбранной плате измерениями.

Переход реалистичен, но это аппаратная версия продукта. Потребуются разводка платы, питание, антенна, прошивка, корпусные испытания и повторное измерение энергобюджета. Сервер, модель событий и API при этом остаются общими.

Целевая задача

IMU фиксирует короткое временное окно. Модель не оценивает безопасность конструкции и не определяет виновника. Она возвращает наблюдаемый класс:

stationary / motion

Адаптация частоты BLE и подтверждение фактического перемещения актива.

vibration

Продолжительная технологическая вибрация, которую не следует считать отдельным ударом.

impulse

Короткое механическое воздействие, требующее передачи контекста на Edge.

tilt / tamper

Изменение ориентации, снятие или нарушение крепления сенсора.

unknown

Низкая уверенность или новый паттерн. Сырое окно сохраняется для разметки.

Событийный конвейер

Частота выборки, длина окна и диапазон акселерометра выбираются по стендовым данным. Слишком низкая частота пропустит короткий импульс, слишком высокая увеличит RAM, вычисления и энергопотребление.

Инструменты

TFLite Micro

Подходит для компактной нейросети. Использовать только нужные операции через MicroMutableOpResolver, а не включать весь набор операторов.

CMSIS-NN

Оптимизированные int8-ядра для Cortex-M. Эффект проверяется на конкретной сборке и поддерживаемых операциях.

Кодогенерация дерева

Для небольшой feature-модели может быть проще и компактнее runtime нейросети.

Edge Impulse

Ускоряет сбор, DSP и deployment прототипа, но формат данных, экспорт и воспроизводимость не должны зависеть только от облачной студии.

Почему пример с AllOpsResolver не годится как production-шаблон

// Концептуально: регистрируем только операции нашей модели.
tflite::MicroMutableOpResolver<4> resolver;
resolver.AddConv2D();
resolver.AddDepthwiseConv2D();
resolver.AddFullyConnected();
resolver.AddSoftmax();

// Размер arena не угадывается: его подтверждают AllocateTensors()
// и измерением пикового использования в целевой сборке.

Интерпретатор не следует заново создавать и аллоцировать для каждого события без причины. Вход int8-модели заполняется квантованными значениями с корректными scale/zero-point, а не произвольным float. API библиотеки меняется, поэтому рабочий пример привязывается к версии зависимостей и проверяется CI-сборкой.

Оценка батареи строится по измеренному профилю:

E_day =
  E_sleep +
  E_imu +
  N_events × (E_window + E_inference + E_ble) +
  E_heartbeat

Номинальные 2700 мА·ч не делятся механически на средний ток без учёта саморазряда, температуры, импульсной нагрузки и эксплуатационного резерва.

Данные и проверка

  1. Собрать стендовые и нормальные эксплуатационные окна с разными креплениями.
  2. Размечать по независимому наблюдению; не использовать триггер как готовую истину.
  3. Разделить train/test по активам и дням, а не случайными соседними окнами.
  4. Сравнить правила, feature-модель и 1D CNN.
  5. Сначала запустить модель на Edge в shadow mode.
  6. Переносить подтверждённую модель на выбранную цель: nRF52832 для минимального варианта либо nRF52840/nRF5340 для сенсорной версии.
  7. Проверить сбои сенсора, насыщение, повреждённые пакеты, unknown и откат модели.
TinyML не получает полномочий безопасности. Его выход — характеристика сенсорного события. Он не подтверждает исправность стеллажа, не устанавливает виновника и не управляет движением техники.

Критерий готовности TinyML

Модуль готов к полевому пилоту, когда одновременно известны качество на независимой выборке, worst-case RAM/Flash, задержка, измеренный энергопрофиль, версия модели, поведение unknown и безопасный откат. Одной демонстрации инференса недостаточно.
